# PRD: 라핀 에이전시 랜딩페이지 (코드네임: lapin-web)

> 1인 홈페이지 제작 에이전시 "라핀"의 브랜드 랜딩페이지 - 고객 문의 접수 및 어드민 관리 기능 포함

---

## 1. 제품 비전

- **한 줄 요약**: 라핀의 서비스와 작업물을 보여주고, 고객 문의를 웹으로 접수·관리하는 랜딩페이지
- **왜 만드는가**: 1인 에이전시로서 신뢰감을 주는 브랜드 페이지가 없으면 잠재 고객에게 전문성을 전달하기 어렵다. 카카오톡·DM으로 분산되는 문의를 한 곳에서 수집하고 현황을 파악할 수 있는 구조가 필요하다.
- **타겟 사용자**
  - 방문자: 랜딩페이지 또는 기업 홈페이지 제작을 검토 중인 국내 소상공인/스타트업
  - 운영자: 라핀 대표 (1인) - 어드민 페이지에서 문의 확인 및 상태 관리

---

## 2. 핵심 원칙

| 원칙 | 설명 |
|------|------|
| 애플 스타일 | 순백 배경, 초대형 타이포, 풍부한 여백. 불필요한 시각 요소 배제 |
| 단순하게 | 라이브러리 최소화, Server Component 우선, 인터랙션 필요한 곳만 Client |
| 빠른 런칭 | 포트폴리오 코드 하드코딩, 알림 없음 - MVP 배포 후 필요 시 확장 |
| 문의 중심 | 모든 섹션의 최종 목적지는 문의 폼으로의 자연스러운 유도 |

## 3. 기능 요구사항

### P0 - Must Have (MVP)

#### F1: 랜딩페이지 (7개 섹션)

- **유저 스토리**: 방문자가 라핀의 서비스와 작업물을 보고 문의 여부를 결정할 수 있다
- **섹션 구성**

  | 섹션 | 내용 |
  |------|------|
  | Navbar | 라핀 로고, 섹션 앵커 링크, "문의하기" CTA 버튼 |
  | Hero | 풀스크린 순백 배경. `text-7xl~8xl` 대형 헤드라인 + 서브카피 1줄 + CTA 2개 (무료 상담 신청 / 포트폴리오 보기) |
  | Services | 랜딩페이지 / 기업 홈페이지 - 아이콘 + 제목 + 1줄 설명 카드 2개 |
  | Process | 4단계: 상담 → 기획 → 개발 → 런칭 (번호 + 제목 + 설명) |
  | Portfolio | 작업 사례 카드 3~4개 (이미지 + 카테고리 태그 + 프로젝트명). 코드에 하드코딩 |
  | Pricing | Basic / Standard / Premium 카드 3개. 금액 미표시, "문의 시 안내" 처리. 포함 항목 리스트 |
  | FAQ | 자주 묻는 질문 5개. 아코디언 (useState) |
  | Contact | 문의 폼 (아래 F2 참고) |
  | Footer | 라핀 브랜드명, 사업자 정보 |

- **디자인 규칙**
  - 배경: `#ffffff` (흰색) / 섹션 교차 배경: `#f5f5f7` (연한 그레이)
  - 주 텍스트: `#1d1d1f`, 보조 텍스트: `#6e6e73`
  - CTA 버튼: `#0071e3` 라운드 (rounded-full)
  - 섹션 패딩: `py-24 md:py-32 lg:py-40`
  - 폰트: Inter, `-apple-system` 계열
  - 헤드라인 자간: `letter-spacing: -0.03em`

#### F2: 고객 문의 폼

- **유저 스토리**: 방문자가 이름, 연락처, 이메일, 문의 내용을 입력하고 제출하면 운영자에게 전달된다
- **폼 필드**: 이름(필수), 연락처(선택), 이메일(필수), 문의 내용(필수)
- **제출 흐름**: 클라이언트 `fetch('/api/contact', POST)` → 서버에서 Supabase `contacts` 테이블 INSERT → 성공/에러 메시지 표시
- **유효성 검사**: 이름, 이메일, 문의 내용 비어있으면 제출 차단. 이메일 형식 기본 검사
- **상태 표시**: 제출 중 로딩 → 성공 메시지 ("문의가 접수되었습니다") → 폼 초기화

#### F3: 어드민 - 문의 목록 조회

- **유저 스토리**: 운영자가 로그인 후 접수된 문의를 최신순으로 확인하고 상태를 관리할 수 있다
- **접근 경로**: `/admin` - 미인증 시 `/admin/login` 자동 리다이렉트
- **로그인**: 이메일 + 비밀번호 (Supabase Auth). 별도 회원가입 없음, 대시보드에서 계정 수동 생성
- **문의 목록**: 이름, 이메일, 연락처, 문의 내용 요약, 접수일시, 상태 배지 표시
- **상태 관리**: 각 문의별 상태 변경 가능 - `new` → `read` → `replied`
- **정렬**: 최신 접수순 기본

## 4. 기술 제약

- **베이스 스택**: Next.js 14 (App Router), Tailwind CSS v3, TypeScript
- **백엔드**: Supabase (PostgreSQL + Row Level Security + Auth)
- **배포**: Vercel (자동 CI/CD)
- **아키텍처 원칙**: Server Component 기본, `'use client'`는 인터랙션 필요한 곳만 (ContactForm, FAQSection, Navbar, AdminLogin)

- **데이터 모델**

  ```typescript
  // contacts 테이블
  interface Contact {
    id: string;           // uuid
    name: string;
    email: string;
    phone: string | null;
    message: string;
    status: 'new' | 'read' | 'replied';
    created_at: string;   // timestamptz
  }
  ```

- **RLS 정책**
  - INSERT: 모든 사용자 허용 (문의 제출)
  - SELECT / UPDATE: 인증된 사용자만 허용 (어드민)

- **외부 의존성**

  | 패키지 | 용도 |
  |--------|------|
  | `@supabase/supabase-js` ^2.45 | DB 클라이언트 |
  | `@supabase/ssr` ^0.5 | Next.js App Router 쿠키 세션 |
  | `lucide-react` ^0.400 | 아이콘 |

- **성능 목표**: Lighthouse Performance 90+, LCP 2.5초 이하 (이미지 next/image 최적화)
